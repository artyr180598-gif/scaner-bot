# Потоковые уведомления об уровнях

Команда `/live` показывает состояние соединения, число наблюдаемых монет,
возраст последней сделки и счётчики доставки/пропусков. Она защищена той же
проверкой Telegram ID, что и остальные команды бота. Если открыт ввод тикера,
сначала выйдите через `/menu`.

Назначение: убрать ожидание очередного полного сканирования для пересечения
уровней заранее отобранных сценариев. Это НЕ новая прибыльная стратегия, НЕ
восстановленная стратегия RID и НЕ прогноз движения до его появления.

Модуль подписывается на публичный поток Bybit `publicTrade` для максимум 20
сценариев текущего раннего радара. Независимая задача обновляет список кандидатов
по умолчанию каждые 5 минут (LIVE_WATCHLIST_INTERVAL_SECONDS), с проверкой раз в
30 секунд. При занятом сканере обновление откладывается, свежий результат
повторно не запрашивается. Нет сценариев — нет уведомлений. Binance в
этом модуле не поддерживается. Закрытия свечи для события пересечения не ждёт.

Проверки:
- Наблюдаемая сделка внутри уровня, затем сделка за уровнем в сторону сценария.
- Первое сообщение после подключения только задаёт исходную цену.
- События старше 5 секунд, обратные временные метки и нечисловые цены отклоняются.
- После разрыва между наблюдениями более 5 секунд исходная цена задаётся заново.
- Удаление более 0,3% от уровня блокирует оповещение (защитный порог, не доказанное преимущество).
- Сценарий должен быть активным и не истёкшим.
- Используется последняя сделка в пакете: промежуточные касания могут быть пропущены.
- Нет доказательства исполнения доступным объёмом, проверки спреда в момент
  пересечения или определения дальнейшего направления.

Приём данных отделён очередью от Telegram. Очередь ограничена 20 событиями;
переполнение и устаревшие сообщения отбрасываются. Отправка ограничена пятью
секундами. Запись `event_to_api_ack_ms` в логах измеряет время от биржевой сделки
до ответа API Telegram, НЕ время появления уведомления на телефоне. Последние
256 доставленных ключей сохраняются в существующей базе, без папки скриншотов.
Доставка best-effort: возможны пропуски при сбоях и дубль при аварии между
отправкой и сохранением. При нескольких получателях сохраняется факт хотя бы
одной успешной доставки; персональные повторные попытки не реализованы.

Поддерживаются heartbeat, переподключение с паузами до 30 секунд. HTTP
401/403/429 и отклонённая подписка останавливают поток без обхода ограничений.
Остальные функции бота продолжают работать. Ошибки видны в логах. Настройка
`LIVE_RADAR_ENABLED=false` отключает модуль; по умолчанию включён для Bybit.

## Проверки перед выпуском

24 теста изолированной копии основной ветки с изменениями прошли; статические
проверки изменённых файлов также пройдены. Проверены детектор, истечение событий,
очередь, сохранение повторов, независимое обновление списка и имитация WebSocket.
Попытка реального соединения в исследовательской
среде завершилась `ClientConnectorDNSError`: реальная связь Bybit → Railway →
Telegram и задержка на телефоне НЕ подтверждены. Развёртывание без проверки
логов не считается завершённой проверкой. Нулевая задержка не обещается.
