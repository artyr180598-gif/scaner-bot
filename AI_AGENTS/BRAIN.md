## Что проект собой представляет

Telegram-бот-сканер арбитражных связок «спот ↔ перпетуал» между биржами
MEXC / Bybit / OKX / Binance (ccxt + ccxt.pro, WS с REST-fallback, без API-ключей).
Живёт на Railway (worker). Не торгует сам — находит и показывает возможности.

## ❌ ЧТО НЕ РАБОТАЕТ / ОТКАЗАЛИСЬ (НЕ ПОВТОРЯТЬ)

1. **Плоский порог 2% как основа сигналов (v2)** — на ликвидных парах
   исполнимый чистый спред почти всегда 0.05–0.8%; порог почти никогда не
   срабатывает (0 сделок на majors за 2 года в бектесте). Причина жалобы
   «мало сигналов». Решение = адаптивный z-score (v3), порог оставлен как
   режим `fixed` для совместимости.
2. **Учёт комиссий только на вход** (сема v2: NET = гросс − 0.15%) —
   занижает издержки вдвое: связку надо ещё ЗАКРЫТЬ (ещё ~0.15% taker).
   В v3 любое решение проходит через `roundtrip_net`. НЕ ВОЗВРАЩАТЬСЯ.
3. **Чистая mean-reversion спреда на ОДНОЙ бирже (basis) без funding** —
   basis Binance спот↔перп обычно |спред| < 0.15%, round-trip 0.3%+slippage
   съедает всё: REV-класс без аномалий (z≥1.5σ) не входит, «просто широкий»
   спред входить нельзя (проверено: smoke-прогон NEW_NOFUNDING с слабым
   гейтом = 0 сделок на majors).
4. **Наивный carry («funding > 0.01%/8ч → входим и держим»)** — комиссии
   съедают сбор: PF 0.9–1.9, при стрессе проскальзывания умирает. Работает
   ТОЛЬКО с квантовыми гейтами (z-пол, round-trip, persistence, выбор
   горячих пар) — см. разрыв NEW_CARRYONLY vs CARRY_NAIVE (2.5% vs 4.5%/год... точнее 4.5 vs 2.8).
5. **Выход carry-позиции по «funding мигнул 2 бара»** — чёрн: позиции
   держались ~3 дня, комиссии 0.3% не окупались. Заменено на трейлинг-окно
   72 ч с порогом −0.10% (выходим, только если реально платим).
6. **CARRY-позиции в одном слоте с REVERSION** — открытая carry-позиция
   блокировала rev-вход на той же паре (а самые горячие пары совпадают).
   Исправлено раздельными слотами `key#CARRY` / `key#REV` + раздельные
   аллокации (5%/10%). После фикса NEW вырос с +11% до +19.3% (2 года).
7. **Одинаковая аллокация на классы** — медленный carry разжижал быстрый
   reversion. Раздельные `alloc_fraction` (carry) / `rev_alloc_fraction` (rev).
8. **Получение исторических данных напрямую с бирж из песочницы Arena** —
   сеть песочницы бело-списочная: api.binance.com/bybit/okx (прямо) = блок;
   data.binance.vision = блок; raw.githubusercontent/jsdelivr/huggingface = блок.
   Работают: `github.com` (git clone!), `api.github.com` (в т.ч. содержимое
   файлов через git blobs), `codeload.github.com`, `pypi.org`,
   `files.pythonhosted.org`, `registry.npmjs.org`. fetch_page-инструмент
   платформы умеет OKX и Bitget API (см. DATA_SOURCES.md) — но качать через
   него мегабайты нельзя (жрут контекст).
9. **Гонять бектест на нечётных данных**: pandas 3.x вернул `datetime64[us]`;
   делить `astype('int64')` на 1e6 как наносекунды НЕЛЬЗЯ — все спот-файлы
   опустели (эпизод 2026-08-30, починено в `prepare_data.py` через
   `tz_convert→tz_localize(None)→astype('datetime64[ns]')`).
10. **Кормить SignalEngine только связками выше порога** — z-score считается
    по «обрезанному» распределению и врёт. Поэтому `_observe_engine` в
    сканере пишет ЛУЧШИЙ спред каждой пары КАЖДЫЙ скан независимо от порога,
    а в бектесте движок кормится всеми барами.
11. **Направленный прогноз цены (RSI/MACD/EMA/BB/«свой индикатор») как замена
    арбитража** — проверено на 26 стратегиях, 49 монетах, 4.5 годах, IS/OOS:
    после комиссий edge нет (лучшее OOS — MOM_WEEKLY PF 1.09, ниже порога 1.20).
    Высокий winrate mean-reversion (BB_BOUNCE 55%) приходит с отрицательным
    мат.ожиданием. Не путать с рабочим v3 (delta-neutral, PF 3.33).
12. **Vol-target / DD-circuit / cash-stack на направленном picker** — режет яму
    ценой нулевого OOS1 (CHAN_VD20 PF 1.05, BOOK_RP PF 1.06). LOWVOL_STACK
    in-market 23% — не стратегия. Не повторять.

## ⚠️ ОТКРЫТЫЕ ВОПРОСЫ / ОГРАНИЧЕНИЯ (что улучшить следующим агентам)

1. **Live-валидация funding**: `/top`–/`signal` дотягивают funding только для
   топ-3/топ-10 кандидатов (экономия API). CARRY-оценка в таблице может быть
   неполной для остальных строк. Идея: фоновая предзагрузка funding для топ-30
   пар по |спред| раз в 10 мин.
2. **Кросс-биржевой спред в бектесте не смоделирован** (данных нет — только
   Binance). Двухклассовое ядро универсально для любой пары бирж, но цифры
   бектеста относятся к basis-режиму. Если найдёте источник синхронных
   мультибиржевых кладлов (см. DATA_SOURCES.md «Где искать») — прогнать.
3. **Полужизнь AR(1)** в live считается, но гейт `MAX_HALFLIFE_HOURS=0`
   (выключен) — в бектесте не понадобился. Можно включить после анализа.
4. **EpisodeTracker live** оценивает захват консервативно (без funding при
   удержании). Это ОК, но помнить при чтении /stats.
5. `MIN_HISTORY=360` (30 мин) — компромисс быстрого старта; в бектесте
   использовалось 90 баров × 4 ч = 15 дней. Для максимальной строгости можно
   поднять до 2160 (3 ч), ценой медленного прогрева после старта.
6. **maker-режим выхода** (лимитки вместо taker) не моделировался — реальный
   PnL может быть выше бектестного.
