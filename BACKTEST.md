# Бэктестинг (честный)

Мы **не подгоняем** уверенность под прибыль. Наоборот, бэктестер считает
winrate по корзинам уверенности, чтобы показать, есть ли связь между
`signal_confidence` и исходом — а если связи нет, не скрываем это.

## Метод

Walk-forward на истории свечей:

1. Индикаторы считаются один раз на всей истории (они причинные, без look-ahead).
2. Для каждого бара после прогрева модель строит сигнал (направление + confidence).
3. Если есть направление и `confidence >= 40` — считаем гипотетическую сделку:
   вход по цене закрытия, выход по TP1 (1R) или SL, что сработает раньше
   (в пределах `LOOKAHEAD` баров).
4. Результаты группируются по корзинам уверенности.

Это **статистика согласия факторов**, а не обещание профита.

## Запуск

```bash
source .venv/bin/activate
python - <<'PY'
import asyncio
from crypto_advisor.backtest.engine import run_backtest_synthetic
res = asyncio.run(run_backtest_synthetic(limit=300))
print(res.summary())
PY
```

## Пример вывода (синтетика, 8 монет, 1h, ~300 свечей)

```
Сделок: 888
  40-59%: n=389 winrate=60% pnl=+719.81%
  60-79%: n=424 winrate=75% pnl=+1572.33%
  80-99%: n=75  winrate=52% pnl=+95.89%
```

> ⚠️ Это **синтетические** данные (генератор тренда + шума), а не реальный
> рынок. Числа показывают, что движок *способен* выдавать столько-то сделок
> с такой-то статистикой — но ничего не говорят о реальной доходности.
> Для продакшена подставь реальные свечи (см. `ExchangeGateway.fetch_candles`).

## Важно

- `confidence` — это **согласие групп факторов**, а не вероятность прибыли.
  В UI (и в тексте совета) всегда есть дисклеймер.
- На реальном боковике бот должен молчать (как и старая версия). Если
  бэктест на реальных данных показывает winrate ~50% во всех корзинах —
  это честный знак, что стратегия не предсказывает.
