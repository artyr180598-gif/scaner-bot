# CryptoPilot 3.1

Telegram‑помощник для анализа ликвидных бессрочных USDT‑фьючерсов Bybit или Binance.
Система не открывает позиции и не имеет модуля исполнения ордеров: она собирает публичные
рыночные данные, отбрасывает слабые ситуации и формирует объяснимый план `LONG`, `SHORT`
или `NO TRADE`.

## Что делает бот

- автоматически проверяет рынок с заданным интервалом;
- сначала фильтрует торгуемые USDT perpetual по обороту и bid/ask‑спреду;
- делает быстрый отбор universe, затем углублённо анализирует shortlist;
- отдельный ранний радар ищет сжатие Bollinger/Keltner/ATR/EMA до пробоя, разделяет
  `WATCH` и `CONFIRMED_WATCH`, выдаёт основной и альтернативный уровни выхода диапазона;
- отдельный `🐋 Smart Money Radar` ищет совпадение market structure, RVOL, роста open interest,
  taker-flow, старшего тренда, funding и небольшого подтверждения стаканом; стадии `WATCH` →
  `ARMED` → `ENTRY` не смешиваются с основными торговыми сигналами;
- использует только закрытые свечи и три таймфрейма (по умолчанию 15m/1h/4h);
- учитывает EMA 20/50/200, RSI, ATR, ADX/DMI, MACD, Bollinger/Keltner, объём, пробой
  структуры, efficiency ratio, Choppiness, CMF, relative volume, VWAP, Trend Guard
  (Supertrend + EMA), funding, open interest, taker flow, дисбаланс стакана,
  long/short crowding, относительную силу к BTC и рыночный режим;
- автоматически различает бычий/медвежий тренд, флэт и переходную фазу, ужесточая требования
  в нестабильном режиме;
- использует отдельные подтверждённые пороги для LONG и SHORT;
- отправляет автоматический сигнал только выше строгого порога уверенности;
- выдаёт зону входа, три ограниченные ступени набора 50/30/20, технический стоп,
  TP1/TP2/TP3, горизонт 1–72 часа, рекомендуемое плечо 1–2x (максимум 3x),
  размер позиции по заданному риску, причины и риски;
- хранит историю в SQLite, ограничивает общий/однонаправленный риск и не повторяет одинаковый
  алерт до окончания cooldown;
- автоматически сопровождает отправленные сигналы в paper-режиме, фиксирует вход, SL, TP2,
  истечение и реальную expectancy после комиссий;
- показывает статистическую частоту успеха и 95% доверительный диапазон только после фактических
  paper-наблюдений; слабая свежая статистика автоматически повышает порог алерта;
- выполняет консервативный walk‑forward backtest без утечки будущих свечей;
- имеет `/healthz`, `/readyz` и `/metrics` для Railway.

Качество в сообщении — **внутренний рейтинг сетапа от 0 до 100**, а не обещание процента
выигрышных сделок. Реальная частота успеха показывается отдельно из накопленной paper-статистики
с размером выборки и доверительным диапазоном. Если данных или edge недостаточно, правильный
результат — `NO TRADE`.

## Telegram

Кнопки и команды:

- `🔎 Сканировать рынок` / `/scan` — ручной полный скан;
- `🪙 Анализ монеты` / `/analyze BTC` — подробный разбор одной монеты;
- `⚡ До импульса` / `/early` — наблюдения до пробоя; вход только после триггера;
- `🐋 Крупный капитал` / `/smartmoney` — отдельный радар структуры + RVOL + OI + taker-flow;
- `⭐ Лучшие сигналы` / `/best` — последние сохранённые планы;
- `📊 Бэктест` / `/backtest ETH` — walk‑forward тест на 1h;
- `📈 Результаты` / `/performance` — фактическая paper-статистика LONG/SHORT;
- `⚙️ Статус` / `/status` — Telegram, API и автомониторинг;
- `❓ Помощь` / `/help` — правила использования.
- `/menu` — принудительно обновить Telegram-клавиатуру после деплоя.

Доступ разрешён только ID из `TELEGRAM_CHAT_ID`. Это обязательный защитный барьер.

Ранний радар автоматически присылает только стадию `CONFIRMED_WATCH`: направление 4h
подтверждено Trend Guard, на 15m появился выход с относительным объёмом. Это всё равно
наблюдение, не торговый сигнал. Многолетний тест показал отрицательную expectancy
механического входа по радару, поэтому он не создаёт paper-сделку и не показывает
выдуманную вероятность. Разрешение на торговый план даёт основной подтверждённый сканер.

При каждом успешном старте бот отправляет авторизованным чатам версию и commit SHA вместе
с новой клавиатурой. Если кнопка `⚡ До импульса` не появилась, `/menu` восстанавливает её.

## Railway

1. Подключите репозиторий как Railway service.
2. Добавьте Variables:
   - `TELEGRAM_BOT_TOKEN` — токен BotFather;
   - `TELEGRAM_CHAT_ID` — ваш numeric ID; несколько ID можно указать через запятую;
   - `EXCHANGE=bybit` либо `EXCHANGE=binance`.
3. При необходимости измените параметры из `.env.example`.
4. Railway автоматически использует `Dockerfile`, запускает `python -m cryptopilot` и
   проверяет `/healthz`.
5. Для постоянной истории подключите Railway Volume и задайте `DATA_DIR=/data`.

Старые имена переменных `TELEGRAM_TOKEN`, `BOT_TOKEN`, `TG_TOKEN`, `BOT_API_TOKEN`,
`TELEGRAM_USER_ID`, `CHAT_ID`, `ALLOWED_CHAT_IDS`, `ADMIN_CHAT_IDS` и `ADMIN_ID`
поддерживаются, чтобы существующий деплой не сломался. Также сохранена совместимость с
`MIN_VOLUME_USD_24H`, `TOP_N_SYMBOLS` и `HTTP_TIMEOUT`.
Ключи Bybit/Binance для анализа не нужны: используются публичные market-data endpoints.
Снимок стакана не является самостоятельным сигналом и получает только малый вес.

## Логика решения

```text
active USDT perpetuals
  → liquidity/spread filter
  → top universe by turnover
  → quick 1h directional score
  → full 15m + 1h + 4h analysis
  → BTC regime + DMI/efficiency/volatility + Trend Guard + relative strength
  → funding + OI + taker flow + order-book/crowding context + data-quality gates
  → risk plan or NO TRADE
  → LONG/SHORT threshold + paper calibration + portfolio cap
  → Telegram
```

Автоматические пороги должны быть не ниже ручного. LONG блокируется против сильного
медвежьего режима BTC, SHORT — против сильного бычьего. Во флэте и переходной фазе порог
автоматически повышается. Также блокируются устаревшие данные, слабая ликвидность, широкий
спред, конфликт старших таймфреймов, слабый ADX/DMI, рыночный шум, сжатые EMA, волатильностный
шок, сильное отставание от BTC, экстремальный funding и погоня за уже ушедшей ценой.

## Smart Money Radar

Кнопка `🐋 Крупный капитал` запускает отдельный сканер и не меняет основной SignalEngine.
Он сначала проверяет ликвидный universe по закрытым 15m-свечам, затем углублённо анализирует
лучших кандидатов на 15m/1h и только после этого запрашивает более дорогую деривативную
микроструктуру. Это снижает число API-запросов и риск rate-limit.

Рейтинг строится из нескольких независимых групп факторов: BOS/HH-HL/LH-LL, relative volume,
направление 1h, изменение open interest, taker buy/sell flow, близость к границе диапазона,
сжатие волатильности, funding и небольшой вес snapshot-дисбаланса стакана. Рост цены вместе с
ростом OI трактуется сильнее, чем рост цены при падающем OI, поскольку второй случай может быть
закрытием шортов. Сильный перекос funding или слишком большое удаление от VWAP штрафуют score.

Стадии:

- `WATCH` — интересный след потока, но вход не подтверждён;
- `ARMED` — цена у триггера и старший тренд согласован; ждём закрытого 15m подтверждения;
- `ENTRY` — закрытая свеча дала BOS, RVOL повышен, taker-flow/OI не противоречат движению и 1h
  подтверждает направление. Даже эта стадия не означает обязательный рыночный вход после
  вертикальной свечи.

Публичные API не раскрывают личность участника рынка. Поэтому бот не пишет, что «кит точно
купил». Taker-flow используется как прокси дельты по публичным сделкам/агрегатам; это не
полноценный footprint-CVD с историей каждой сделки.

## Самокалибровка и paper tracking

Каждый действительно отправленный автоматический сигнал записывается как paper-сделка.
Бот ждёт касания зоны входа, затем по закрытым 15m-свечам консервативно проверяет SL и TP2.
Если оба уровня коснулись внутри одной свечи, первым считается SL. В расчёте результата
учитываются заданные комиссии и проскальзывание.

До накопления `CALIBRATION_MIN_SAMPLES` бот прямо сообщает, что статистики недостаточно.
После этого он показывает наблюдаемую частоту успеха, 95% интервал, expectancy и profit factor.
Если свежая выборка имеет неположительное ожидание, автоматический порог повышается, но ручной
анализ остаётся доступен. Для сохранения статистики между деплоями Railway нужен Volume.

## Важное ограничение

Фьючерсы высокорискованны. Backtest и рейтинг уверенности не гарантируют будущую
доходность. Перед реальными деньгами используйте paper trading, ограничивайте риск и
проверяйте цену/спред непосредственно на бирже. Бот специально не содержит автоторговлю,
martingale и скрытое увеличение позиции.
