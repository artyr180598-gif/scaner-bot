# Крипто-советник (Telegram)

Телеграм-бот, который ищет монеты **до** сильного движения и объясняет по-русски,
почему именно эта монета и почему именно сейчас. Даёт LONG / SHORT / **WAIT**,
зону входа, стоп, три цели, R:R и размер позиции под ваш депозит.

Это **не** торговый робот: бот не имеет доступа к вашему аккаунту, не ставит
ордера и не хранит ключи бирж. Он аналитик, который отвечает на вопрос
«на что смотреть», а решение и риск — всегда ваши.

---

## Главная идея: искать пружину, а не ракету

Большинство сканеров показывают монеты, которые **уже** выросли на 30% за сутки.
Заходить туда поздно: движение случилось, вы покупаете чужую прибыль.

Здесь отбор построен наоборот — ищем монеты, которые **готовы** двинуться:

| Что ищем | Как измеряем |
|---|---|
| Сжатие волатильности («пружина») | перцентиль ATR, ширина Боллинджера, NR7, choppiness |
| Накопление | OBV/MFI против цены, кластеризация объёма в узком диапазоне |
| Реакция от ключевого уровня | свинги, order blocks, FVG, круглые числа, POC/VA профиля объёма |
| Аномалия объёма без движения цены | z-score объёма против истории |
| Разворот структуры | BOS/CHOCH, sweep ликвидности, HH/HL и LH/LL |
| Дивергенция | RSI/MACD/OBV против цены |
| Позиционирование деривативов | funding rate, изменение open interest |
| Фон рынка | тренд BTC + ширина рынка (breadth) |

И отдельно — **анти-погоня**: монета отсекается, если она уже улетела
(z-score движения, расстояние от хая, вход дальше `ANTI_CHASE_ATR` от зоны).

## Быстрый старт

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt

cp .env.example .env      # впишите TELEGRAM_BOT_TOKEN

# Офлайн-проверка всего конвейера (без сети и без Telegram):
PYTHONPATH=. .venv/bin/python -m app.main --selftest

# Запуск бота:
PYTHONPATH=. .venv/bin/python -m app.main
```

Полезные режимы (без Telegram):

```bash
python -m app.main --modules        # список модулей анализа
python -m app.main --analyze BTC    # глубокий анализ одной монеты в консоль
python -m app.main --scan --limit 20 # прогнать сканер и напечатать топ
python -m app.main --check          # проверка связи с биржами
```

Конфигурация проверяется на старте: опечатка в `.env` даёт понятное сообщение
(`ConfigError`), а не падение посреди ночи.

Всё управление — кнопками. Главное меню:


## Архитектура

Слои односторонние: каждый следующий ничего не знает о предыдущем, кроме
своих входных типов.

```
app/
├── domain/models.py        # данные: Candles, Factor, TradePlan, Signal, ScanReport…
├── indicators/             # математика: core, volatility, profile, structure
├── analysis/               # 37 модулей анализа → Factor'ы (плагин-реестр)
│   └── modules/            #   trend, momentum, structure, smc, volume, levels…
├── scoring/                # свёртка факторов → направление, счёт, уверенность
├── signals/                # planner (план сделки), filters (гейты), explain, engine
├── screening/prescreen.py  # грубый и тонкий отбор монет
├── data/                   # биржи (ccxt), кэш, синтетика для тестов
├── services/               # scanner, journal, watchlist, news
├── presentation/           # render (тексты), keyboards (кнопки), format
└── telegram/               # handlers (тонкий слой), services (composition root)
```

**Идея заимствована у freqtrade и OctoBot, код — свой.** От freqtrade — подход
«информативных» таймфреймов (старшие ТФ строятся из базового и добавляются
к признакам) и абстракция провайдера данных. От OctoBot — подключаемые
«оценщики»: каждый модуль анализа возвращает независимый `Factor`, а решение
принимает отдельный слой скоринга, а не один модуль.

### Модули анализа

`python -m app.main --modules` показывает реестр: **37 модулей в 11 группах**.

| Группа | Модулей | Что оценивает |
|---|---|---|
| trend | 3 | EMA-стек, наклон, supertrend, тренд старших ТФ |
| momentum | 6 | RSI, MACD, Stochastic, ADX, дивергенции |
| structure | 4 | BOS/CHOCH, HH/HL, свинги, фазы рынка |
| smc | 3 | order blocks, FVG, sweep ликвидности |
| volume | 3 | OBV, MFI, аномалии объёма, дельта |
| levels | 3 | ближайшие уровни, POC/VA, круглые числа |
| derivatives | 3 | funding, open interest, базис |
| context | 2 | тренд BTC, ширина рынка |
| potential | 5 | сжатие, накопление, расстояние до целей |
| quality | 4 | свежесть данных, ликвидность, ширина спреда |
| sentiment | 1 | новости (опционально, малый вес) |

Модуль — это чистая функция `features → Iterable[Factor]`. Он не ходит в сеть,
не падает (его исключение изолируется) и не знает про Telegram.

**Добавить свой модуль** — один файл в `app/analysis/modules/`:

```python
from app.analysis.base import AnalysisModule, Group
from app.domain.models import Factor

my_module = AnalysisModule(
    name="мой_фактор",
    group=Group.MOMENTUM,
    func=lambda f: [Factor("мой_фактор", Group.MOMENTUM, score=0.6,
                           evidence="что именно увидели", weight=0.8)],
    description="короткое описание по-русски",
)
```

Дальше он автоматически участвует в скоринге, в `--modules`, в selftest и в тестах.

## Как считается уверенность

**Уверенность — это сила согласия независимых групп аргументов, а не вероятность
прибыли.** Это не фигура речи: на 10 345 сделках по реальным данным связь
«уверенность → результат» отсутствовала (см. `AI_AGENTS/BRAIN.md`), поэтому
бот никогда не обещает доходность.

Механика:

1. Факторы схлопываются в группы (взвешенное среднее внутри группы) — иначе
   пять коррелирующих индикаторов голосовали бы как пять независимых мнений.
2. Итоговый счёт — взвешенное среднее по группам; группы с `|score| < 0.10`
   не попадают в знаменатель (иначе реальный сигнал размазывался бы до 0.2).
3. Уверенность ограничена числом **согласных** групп: 1 группа → потолок 4.0,
   2 → 5.8, 3 → 7.2, 4 → 8.4, 5 → 9.2.
4. Множители: потенциал движения (×0.85…1.10), качество данных (пол ×0.55),
   достоверность данных (×0.7…1.0).
5. Принудительный **WAIT**, если `|счёт| < 0.12` или согласных групп меньше двух.

Дальше гейты публикации (`app/signals/filters.py`): уверенность, R:R, потенциал,
качество данных, ликвидность, свежесть свечей, размер стопа, «погоня за ценой».
Каждый отказ имеет причину на русском — её видно в WAIT-карточке.

## План сделки

* **Вход — зоной**, а не «по рынку»: незаполненный order block / FVG / сильный
  уровень в пределах 3 ATR с правильной стороны, иначе лимитная лесенка.
* **Стоп** — за структурой: дальше из «край зоны ∓ 1.5 ATR» и «свинг/OB ∓ 0.2 ATR»,
  в коридоре 0.9–4.5 ATR.
* **Три цели** — от магнитов (уровни, POC, проекции) с минимальными R
  1.1 / 2.0 / 3.2; если магнитов нет — 1.5 / 2.5 / 4.0 ATR. Фиксация 35/35/30%.
* **Объём позиции** — от риска на сделку и расстояния до стопа;
  плечо не выше `MAX_LEVERAGE` (по умолчанию 3.0), даже если стоп узкий.

## Журнал и честная статистика

Каждый опубликованный сигнал пишется в журнал (`DATA_DIR/journal.json`).
Дальше бот сам сверяет его с реальными свечами и закрывает: **стоп** (если в
одном баре задеты и стоп, и цель — засчитывается стоп, внутрибарный порядок нам
неизвестен), **TP1/TP2/TP3**, **EXPIRED** по горизонту.

Кнопка «📊 Статистика точности» показывает винрейт, средний R и **калибровку по
корзинам уверенности** — то есть честно отвечает на вопрос «работает ли вообще
число, которое бот называет уверенностью».

## Настройка

Все ключи описаны в [`.env.example`](.env.example) (есть тест, который следит,
чтобы документация не расходилась с кодом). Главное:

| Профиль | мин. уверенность | мин. R:R | риск/сделку | плечо |
|---|---|---|---|---|
| `conservative` | 6.5 | 1.8 | 0.5% | 2.0 |
| `moderate` (по умолчанию) | 5.5 | 1.6 | 1.0% | 3.0 |
| `aggressive` | 4.5 | 1.4 | 2.0% | 5.0 |

Чем выше профиль, тем реже сигналы: это плата за качество, а не баг.

## Разработка

```bash
# Тесты (офлайн, без сети и без Telegram):
PYTHONPATH=. .venv/bin/python -m pytest tests/ -q

# Офлайн-гейт качества (режимы рынка, продуктовые пороги, рендер):
PYTHONPATH=. .venv/bin/python -m tools.selftest

# Walk-forward прогон реального движка по истории (исполнение планов, R, PF,
# калибровка уверенности). На реальных данных:
PYTHONPATH=. .venv/bin/python -m tools.backtest_engine --source data/csv --limit 20
# Без реальных данных — смоук на синтетике (это НЕ оценка прибыли):
PYTHONPATH=. .venv/bin/python -m tools.backtest_engine --synthetic breakout,range --seeds 1,2
```

Тесты проверяют не «не упало», а поведение: отсутствие заглядывания в будущее
у индикаторов, совпадение RSI с рекурсией Уайлдера, схлопывание групп,
потолок уверенности по числу согласных групп, консервативность исходов в
журнале, каждый гейт публикации, весь транспортный слой Telegram на подделках,
соответствие `.env.example` коду.

Принципы, которые стоит соблюдать при правках:

* Индикаторы возвращают `pd.Series` той же длины и **не смотрят в будущее**.
* Модули анализа чистые и не падают: исключение одного модуля не роняет анализ.
* Объём/структура читают последний **закрытый** бар, а не формирующийся.
* Никаких обещаний доходности в текстах: это проверено и запрещено опытом проекта.

## Что проверено, а что нет

**Проверено** (тестами и офлайн-гейтом): конвейер от синтетических данных до
карточки сигнала, скоринг, гейты, журнал, интерфейс, конфигурация. Плюс
walk-forward прогон движка (`tools/backtest_engine.py`) на синтетике шести
режимов: 1420 анализов → 129 сделок, поведение по режимам осмысленное
(в боковике убыток, на «уже улетевших» почти не торгует), а калибровка
уверенности перевернута — как и на реальных данных v4. Отчёт:
`backtest/results/engine_v2_synthetic_product.md`.

**Не проверено в этой среде:** работа против живых бирж — API Binance/Bybit/OKX
отсюда недоступны, поэтому реальные запросы не выполнялись. Перед запуском
прогоните `python -m app.main --check` и `--analyze BTC` со своей машины.

**Что показали бектесты на реальных исторических данных** (`AI_AGENTS/BRAIN.md`,
`backtest/`): направленная стратегия v4 на 11 крупных парах за 2021–2026
(10 345 сделок, комиссия 0.16%) дала winrate 47.6%, PF 1.02, средний R ≈ −0.02 —
то есть **без преимущества**. Отсюда два жёстких вывода, зашитых в код:
никаких обещаний прибыли и обязательное схлопывание групп с потолком уверенности.
